# Red Flag — session writeup 2026-08-17

One-day working session: the automatic red-flag activation mechanism, a live
field monitor (in-game + Python GUI), a deep damage model, and three crash
classes found and fixed. All work is trial-stage; nothing is shippable.

---

## 1. What the session produced

### 1.1 Automatic red-flag activation (the original request)

`check_auto_redflag()` was hardened and re-enabled for guarded testing:

- **Settled-race gate** (`race_is_settled()`): GameState 5/7 × RacePhase 3/5,
  excluding RacePhase 2 (grid) and 8 (done). The values are EVIDENCE-BASED,
  not from docs 49: a live yellow-flag race reads GameState=5, RacePhase=5
  (sample-stable); docs 49's "7=race running / 5=FINISHING" is contradicted
  by the live read and by the mods' own proven usage (pace_probe gated on
  RacePhase==5).
- **Native yellow read without calling the game**: `sub_49BAD0` HANGS when
  called from a foreign thread (verified: worker frozen, module unkillable).
  Replaced with `native_yellow_read()` — pure memory reads (steward
  0x8ACEE0 zone table, 29 zones, state 2 = yellow), calibrated end-to-end
  against a displayed flag.
- **Fresh-cluster semantics**: 3+ crash-terminal cars (Active=0 + engine off
  + damage evidence), each confirmed 4 s, within a 5 s window, while the
  yellow has persisted 3 s. Manual triggers arm the same 2-min cooldown.
- **Yellow counter frozen while paused** (race time, not wall time).

### 1.2 The field reviewer (status for ALL drivers)

- `tools\field_reviewer.py` — read-only ctypes module, stdlib only. Reads
  every vehicle (cap raised 26 → 40 for big grids) and classifies:
  player / running / stalled / stopped / crashed / damaged / terminal /
  retired / inactive / in pits / grace / offline.
- Deep damage model per car: 4 component lives (engine 0x3D70, brakes
  0x3D74, gearbox 0x3D78, suspension 0x3D7C — seconds remaining, FACT), both
  wings (front 0xCD4/0xD14, rear 0xD18/0xD58), carConditions decode
  (1 = wing/body, 2 = wheel-loss/severe — FACT), and a 0–100 damage score.
- `tools\field_gui.py` — dark-themed tkinter GUI: color-coded driver table
  (DMG + DAMAGE columns), summary badges (live race, yellow 3s, wrecked AI
  now/window, crashed, stalled, stopped, damaged, SEQUENCE phase, HELD,
  cooldown, result), full damage detail on row select. Elevated to read the
  game's shared memory.

### 1.3 The in-game NUMPAD0 monitor

The F10 toggle was moved to NUMPAD0 (F10 is an in-game keybind). The monitor
shows the activation checklist + counters and now survives hot-swaps:
per-instance window class, window destroyed on teardown, shared-memory bridge
(`F1C_REDFLAG_MON`, 14 × uint32) for the Python GUI.

### 1.4 The anti-removal hold

The game retires a stationary wreck after `Vehicle Removal` seconds
(`Matias.PLR`, 10) — garage teleport mid-countdown broke the red-flag
illusion. `hold_wrecks_on_track()` runs during the countdown/pit-wait: reverts
FinishState/RetiredFlag as the game sets them, and pins BOTH the physics
position (0x34E0) and the scene node (the visible object — physics-only
restore caused visible warping). Policy: wrecks are held ONLY during a red
flag; the vanilla rule applies otherwise. Kept for the future safety-car
script.

### 1.5 The `.PLR` question (OPEN)

Current state: `plr_removal_60()` patches the `.PLR` FILE at load (with a
one-time `.bak`). The user wants NO file modifications — a pure in-memory
override. The parsed values live in linked-list heap descriptor nodes
(contiguous float-pattern scan failed); the consumer of the value is not yet
located. A standalone prompt for another LLM was drafted for this task (see
section 5, OPEN-1). The `.PLR` file itself is currently patched to 60 with
the original preserved.

| 3 | Voice line loops | `say_pump()` re-inserted PWS_RED01 every 400 ms while EVENT_TS pending — a long clip ends, AUDIO_BUSY drops, fresh copy queued. | One insert per request; the retry only covers the pre-first-success busy case. |

  state 2, 29 zones at steward 0x8ACEE0).

  one restart crash (#1) was caught and fixed after the fact.
- The 34-car field exercised the MAX_CARS bump; 8-car fields were used for
  verification.
