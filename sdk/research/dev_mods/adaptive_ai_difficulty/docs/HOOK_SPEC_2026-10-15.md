# adaptive_ai_difficulty - hook spec for the strength call (sub_4F1510 at 0x424AA6)

Date: 2026-10-15. Status: DESIGN ONLY. No code built, no game touched, no runtime tool run.
Tiers: FACT = bytes/asm/finding cited; DERIVED = reasoned; OPEN = needs live/code check; CONFLICT = sources disagree.

## 0. Summary

- Hook = retarget the existing 5-byte `call rel32` at 0x424AA6 to a naked stub (same length, no
  trampoline). The stub edits the float argument in place and tail-jumps to 0x4F1510, so the stack and the
  callee's `ret 4` stay as the game wrote them.
- AI cars: argument = native x per-slot multiplier m[k] (default 1.0). Player car: always pass-through.
- Mid-race change: a game-thread task calls sub_4F1510(P, N_k * m_new) once; later native re-inits pass
  through the stub and get N_k * m_new.
- Pace baseline 0x44F4: separate table p[k] (default 1.0 = no write), same game-thread task. Owner D-PACE (section 5).

## 2. Value semantics

- The stub receives a2, the game's value (for AI in race it already includes RQR, per the code path).
  It stores N_k = a2 (native, last seen) and writes a2' = N_k * m[k].
- DERIVED (H7 section 4): sub_4F1510 scales by a2/B and then sets B = a2. A call with target T gives
  state = baseline x T exactly (float rounding only).
- Restore: sub_4F1510(P, N_k) returns the car to native (B = N_k). Multiplier, not absolute: the native value
  follows the slider (dword_7D01A0) and track GDS; an absolute table would ignore them.
- Side effects per call (FACT, `ScaleAudioPitch_004f1510.c`, byte_7D01C4 = 7): per-wheel terms; torque pairs
  (bit 1); gear ratios (bit 2); fuel consumption factor P+14724 = veh+0x3990 (bit 4; NOT FuelLevel veh+0x3984).
  Never change byte_7D01C4 (applies to all cars).

## 3. Hook mechanics

1. Pre-patch validation (section 8). All checks pass before any write.
2. Stub (naked x86). On entry: ECX = P, [esp+4] = float a2, return address 0x424AAB. It:
   a. saves ECX and computes/validates slot k (8.3);
   b. reads m[k] (atomic float written by the worker); if m[k] == 1.0 exactly, car is the player, or mode is
      refused: no change;
   c. else N_k = a2; writes a2 * m[k] back to [esp+4];
   d. restores ECX = P and `jmp 0x4F1510`.
   A C helper (cdecl, float in ST(0)) may do the float math. It must preserve ECX, and the x87 depth must be
   zero on entry (9.1).
3. Patch: write `e8 <rel32 to stub>` at 0x424AA6 (5 bytes), RWX on those 5 bytes, FlushInstructionCache. Keep the
   original 5 bytes. Use the f1c_hook.h expected-bytes rule (`f1c_ida_decompiled/tools/sdk/f1c_hook.h`): install and
   removal fail closed on any mismatch. Never overwrite a foreign hook (MOD_STANDARD R5).

## 4. Threads and frame hook

- The stub runs on the thread that executes AIDriverStructInit. The entry is event-driven: AIDriverStructInit ->
  SceneRenderUpdate, 7 callers (H20 section 2). DERIVED: game/sim thread. OPEN: confirm (H7 open item 5).
- Worker: may write m[k] and p[k] (aligned atomic float, single store), file I/O, bounded logs. Never calls
  sub_4F1510 and never writes veh/P fields (MOD_STANDARD R2/R3).
- Mid-race change: the worker posts a pending apply. A game-thread task via the broker (`f1c_broker.h` post;
  budget 32 tasks / 2000 us, `f1c_broker_abi.h` lines 13-14) validates (8.4) and calls sub_4F1510(P, N_k * m_new).
  Do not install detours at the internal game-update anchor (NEW_MOD_GUIDE runtime rules).
  OPEN: which broker task type runs custom callables; confirm in `f1c_broker*.h` before batch C.
- Pace write (section 5) runs in the same task, after the strength call.

## 5. Pace baseline 0x44F4 (write alongside)

- Snapshot base_k = veh+0x44F4 at first valid sight per AI slot, tagged with session generation.
- Write veh+0x44F4 = base_k * p[k] (default p = 1.0: no write). Write only if live value still equals our last
  write (MOD_STANDARD R8); else skip and log.
- Step rate CONFLICT: SPEC_2026-10-14 says the car walks +/-0.01 per frame; H8 summary says every 4 s. OPEN (test A6).
- D-PACE (owner): recommended strength-only first (p stays 1.0; the SPEC_2026-10-14 controller keeps the pace lever).

## 6. Re-application, restore, unload, session end

- Native re-init (pit route, restart, driver entry): the stub sets N_k = native, writes N_k * m[k].
  Post-event state = baseline x native x m (DERIVED, H20 section 5); no polling. Round trip m=1.5 then 1.0 restores the state (1e-5).
- Restore (unload, session end, mode off): for each slot where live B equals N_k*m_last (own write), call
  sub_4F1510(P, N_k). Then write back `e8 65 ca 0c 00` at 0x424AA6 and verify. If live B differs, skip and log.
- Session end / generation change / unload: drain or cancel pending tasks, clear m, p, N_k, write to no vehicle of a
  dead generation (check dword_5C329C and dword_7C54F0[k] first), remove the stub patch before unmapping (MOD_STANDARD R9).

## 7. Config, gating, logging

- `adaptive_ai_difficulty.ini` (R10): `Enabled=0` (default = vanilla, no patch). `StrengthMult_<k>` for k = 0..29,
  default 1.0. Player is exempt in code; no key can change that. Missing or invalid key -> default. Multiplier
  outside the allowed range (OPEN: proposed 0.5..1.5) -> 1.0.
- Gating (R7): multiplayer, CO-OP, replay: refuse, no patch, read-only (SPEC_2026-10-14 section 4). Detect via broker
  session snapshot (`F1C_BROKER_CAP_SESSION_SNAPSHOT`) and the CO-OP flag used by `coop_mode` (OPEN name).
- Usage (`f1c_usage.h`, counts and codes only). Log `adaptive_ai_difficulty_log.txt` beside the DLL, bounded, written
  by the worker: patch result, refusal code, per apply (slot, N_k, m, B before/after), restore, startup ms (R4).

## 8. Validation before patching (refusal paths)

8.1 Byte patterns. All must match, else refuse (`AAD-P1`), no write:
- 0x424A90, 37 bytes: `d9 05 e8 a3 5e 00 d8 4c 24 30 d9 5c 24 30 8b 54 24 30 52 8d 4e 0c e8 65 ca 0c 00 5f 5e 5d 5b 83 c4 1c c2 04 00`
  (rel32 checked by target: 0x424AAB + rel32 == 0x4F1510).
- 0x4F1510, 16 bytes: `83 ec 08 d9 44 24 0c 56 8b f1 d8 b6 f4 3b 00 00`.
- 0x424790, 10 bytes: `83 ec 1c 53 33 db 55 56 8b f1`.
Read with guarded reads (IsBadReadPtr, as `mf_compat_fetch` does) and compare with memcmp. The exe hash is not the
gate (MOD_STANDARD R6). Keep `ADDRESS_INVENTORY.md` listing every address above with its tier.

8.2 Site state: 0x424AA6 must be exactly `e8 65 ca 0c 00`; anything else -> refuse (`AAD-P2`).
8.3 Per call: 0 <= k < dword_5C329C and veh == dword_7C54F0[k], else pass-through (`AAD-S1`). Player: veh ==
*(0x7C54E8) OR veh+0x32C8 == 0 -> pass-through (`AAD-S2`). If the two disagree, pass-through and log.

8.4 Per apply: B = *(float*)(P+0x3BF4) finite and > 0 (callee divides by it; `ScaleAudioPitch_004f1510.c:17`);
target finite and > 0; m in range. Else skip (`AAD-S3`).

8.5 Host: entry present, magic 0x7B314C50, ABI >= 0x00020000, product id match; else refuse load (MOD_STANDARD host rule).

## 9. Open items gating the build

9.1 x87 depth at 0x424AA6 must be 0 (the fld/fstp pair at 0x424A90/0x424A9A is the only live use). Verify by a
static decode of 0x424790..0x424AAB (capstone, in %TEMP%) before batch C. OPEN.
9.2 CONFLICT, player stored value. H20 (from code) says the player gets curve x RQR (x0.995 in the older text).
Live probe (`aad-stored-strength-player-and-ai-live-2026-10-15`, FACT) says player stored = GDS with no RQR, AI in race
= GDS x RQR. The code applies [0x5EA3E8] before every call outside sessions 3/4/5, so the difference is unexplained.
The design does not depend on it (stub uses native a2; player is pass-through). Resolve by test A4.
9.3 Sim thread identity (H7 open 5) and broker custom-task path (sections 4, 7). OPEN.
9.4 Pit gates (H20 R4, veh+3352/3416) set re-init frequency; pace step rate CONFLICT (section 5). OPEN.

## 10. Live test plan (clean test install only; memory-MCP freshness rules; owner-approved session)

Run only after batch C is built and reviewed. Never on the live game without owner approval.

Acceptance:
- A1 Pattern validation passes on all four exes (static, no game).
- A2 Stub decode: no x87 residue; only the 5-byte site changes; restore bytes equal vanilla (cmp).
- A3 Identity: Enabled=1 with all m = 1.0 -> B of every car equals the vanilla run (1e-6); state hash equal.
- A4 Player and RQR: read B and [0x5EA3E8] for player and 3 AI cars in one race. Confirms or refutes 9.2 (log only).
- A5 Mid-race: m_k = 1.10 for one AI slot at lap N -> B_k = N_k*1.10 within one game tick (1e-5); veh+0x3984
  unchanged; veh+0x3990 changed by the bit-4 ratio (H7 test 3).
- A6 Re-init persistence: force or wait for an AI pit approach; afterwards B_k = N_k*1.10 (not the slider). Log
  the route. Measure pace step rate if p is used (9.4).
- A7 Player untouched: B_player == native after A5 and A6.
- A8 Restore: m_k -> 1.0 mid-race gives B_k == N_k (1e-5); on unload, 0x424AA6 == e8 65 ca 0c 00.
- A9 Three race loads, no fault; startup ms logged (R4); usage summary written.

Refusal paths (each refuses without writing game memory):
- R-1 Byte-flipped copy of an exe in %TEMP% (static): AAD-P1, no patch.
- R-2 Foreign bytes at 0x424AA6: AAD-P2, no write.
- R-3 Multiplayer / CO-OP / replay: refuse, read-only.
- R-4 Missing or invalid ini key: defaults, logged.
- R-5 Slot out of range or pointer mismatch: pass-through, AAD-S1.
- R-6 B zero or non-finite: skip apply, AAD-S3.
- R-7 Unload with a pending apply: drained or cancelled; no call after unmap. R-8 Host protocol fail: refuse to run.
