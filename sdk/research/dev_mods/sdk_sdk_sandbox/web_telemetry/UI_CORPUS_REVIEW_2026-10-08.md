# Web Telemetry: UI, F1 corpus and mod integration review

Date: 2026-10-08. Target: **Lightloader manager 2.2.7**, protected host ABI v2 / Hub 2, broker ABI 15. Status: investigation and proposed implementation plan. No gameplay changes, installation or deployment in this review.

## Assessment

The best next version is a trustworthy race engineer and race observer. The existing dashboard already displays a lot of data; adding more gauges would contribute less than correcting its calculations, showing what is unavailable, and explaining the state of the installed mods.

The current UI can give misleading advice even when its memory capture works perfectly. Its principal problems are incorrect reference comparisons, multiple incompatible representations of the same information, missing data-quality indicators, and disconnected mod state. These are distinct from the earlier native crash investigation: none establishes that telemetry caused the friend's Direct3D crash.

**Recommended order:** correct existing information → unify session/history/data validity → add authoritative mod observations → add measured strategy and lap analysis. Retain the compact timing tower and expandable panes, but make the default view prioritize the next decision.

## What was examined and what was not

- Full embedded HTML/JavaScript and telemetry calculation paths in the preserved legacy source and the SDK sandbox compatibility candidate; four actual navigation tabs: **Pit Wall, Team Principal, Race Control, Full Debug**. Race Pace is a Pit Wall pane, not a separate current tab.
- All six Pit Wall panes: Session, Car Telemetry, Race Control, Timing Tower, Race Pace and Track Map; persistent focus sidebar, map interactions, hidden/unused driver-detail rendering, polling and SSE connection behavior.
- Browser walkthrough of all four tabs using the exact embedded HTML captured from the compiled synthetic harness. Reviewed the default narrow viewport and 1440×900 desktop layout, first with the pathological 104-car fixture and then a readable synthetic 22-car fixture. These were **not real game observations**. The fixture's artificial car positions and timings are not evidence of incorrect native map geometry or timing fields.
- Corpus entry points and findings queries; broker/session/vehicle ABI; relevant raw decompilation references, numbered research papers, later mechanical-simulation corrections, pit-state runtime research, AI research and F1CUI's preserved class/module inventory.
- Development mod sources/contracts and current or dated records: Safety Car, Red Flag, Mechanical Failures, Pit Stop Failures, Race Data Collector, Driver AI Toolkit, Camera Editor, damage commentary, tyre commentary, traffic commentary, plus Season Narrative/career context. Component README statements are not assumed to prove the currently installed DLL or override newer corrections.
- Lightloader 2.2.7 release record, including its correction about the embedded loader payload.

This is a cross-corpus review using indexed prior art and targeted source verification, **not a claim to have read every file or every decompiled function in the F1 tree**. The Java class inventory is navigation evidence, not a recovered implementation of every F1CUI feature. No native process was attached, no live race was driven, and no public-server state was changed.

Evidence vocabulary below: **source-confirmed** means directly visible in reviewed code; **counterexample** means arithmetic reproduces a defect in that code, not a native gameplay test; **proposal** means not implemented; **open** requires further field or gameplay validation. Historical corpus tiers remain those of their original records.

## Existing correctness defects and gaps

Source anchors in this section refer to `f1c_ida_decompiled/mods/sdk_sandbox/web_telemetry/web_telemetry.c` as reviewed. Line numbers are useful navigation, not an ABI.

| ID / priority | Finding and evidence | Required behavior |
|---|---|---|
| C01 / P1 | **Radar measures race progress, not physically adjacent traffic.** Lines 2091–2119 use `lap_number * lap_len + lap_dist`. Counterexample: on a 5,000 m circuit, player lap 10 at 4,990 m and a lapped car lap 9 at 10 m produce −9,980 m, although that car is 20 m ahead around the circuit. | Separate classification gap from on-track proximity. Use cyclic lap distance for forward/backward proximity, retain lap relation as a badge, and validate route/pit branch and spatial separation. Never present this as a collision radar solely from distance along the lap. |
| C02 / P1 | **“LIVE Sx” is not a meaningful live pace delta.** Lines 1996–2036 subtract a complete PB sector time from current partial-sector elapsed time. A 30 s PB produces roughly −30 s at entry, regardless of whether the current lap is faster. | Until a distance-aligned reference trace exists, show sector elapsed and completed-sector PB delta separately. For a real live delta compare elapsed times at the same distance and reject incomplete/invalid references. |
| C03 / P1 | **Fuel average accepts an incomplete first lap and net refuelling.** Lines 1950–1981 initialize fuel when the car is first seen and accept any nonnegative start-minus-end result. Joining with 20 L and crossing at 19.8 L records 0.2 L/lap; 19.8 L then appears to last 99 laps. Burning 3 L while adding 2 L records 1 L consumption. | Establish a complete start-line baseline. Exclude partial, refuelled, missed-crossing, replay/reset and invalid samples; classify pit/SC/RF laps separately. Display sample count, coverage and a range before offering advice. |
| C04 / P1 | **Race status defaults to GREEN without mod authority.** Lines 3528–3530 and 4088–4090 derive it from cached `RC_MODE` incidents. The read-only candidate has no active writer of those legacy command events. It does not read SC/RF ownership. | Separate native phase, local yellows and mod controller state. Missing provider means “SC/RF status unavailable”, never inferred GREEN. Physical SC, VSC and Red Flag must be separate states. |
| C05 / P1 | **Zero RPM is called a dead engine and feeds WILL RETIRE.** Lines 1394–1398 only require race active, position, not-finished, near-zero RPM and crank speed. A stalled/garage/unstarted engine can satisfy these conditions. | Say “engine stopped” from rotational observations; use native finish/reason and a valid mod terminal latch for retirement. Show restartability/ignition only when validated. Do not label a reversible stop guaranteed retirement. |
| C06 / P1 | **History stops after 60 recorded laps.** `MAX_LAP_HISTORY=60`, lines 975 and 1010; storage accepts only `idx < MAX_LAP_HISTORY`. The Race Pace pane renders the last six stored rows, not necessarily the last six actual laps later in a long race. | Keep a recent ring plus durable full-session journal, or retain all laps under an explicit bounded session limit. Publish retained range and loss/truncation; test laps 59–65 and a full long race. |
| C07 / P1 | **Fresh transport is confused with valid individual measurements.** Missing values often become `0`, “NONE”, “intact” or “running”. Per-car mirrors have acknowledged player/AI and LOD limitations; whole-frame age cannot establish each signal's validity. | Each field/group needs value, unit, validity, source, observation time and scope. Unknown/unavailable differs from zero, healthy, off and not simulated. Preserve broker valid-field bits. |
| C08 / P1 | **Connected-but-silent SSE can leave LIVE visible.** Lines 4105–4108 update freshness only on a message/error, with swallowed parse/render exceptions. There is no independent browser deadline for absence of messages. | A monotonic client watchdog must age the last accepted frame even if EventSource has not errored; show transport age separately from game-sample age, pause and replay. Record bounded diagnostics for rejected messages. |
| C09 / P2 | **Browser caches and asynchronous replies are not session-scoped.** `up()` changes the map key at 3378–3379, but pace/incidents/dossier/verification/focus state lack equivalent central reset and generation checks. `/laps`, `/incidents`, `/driver` callbacks accept results unconditionally. | Make generation+capture+vehicle identity mandatory. Clear all dependent caches at a boundary and reject responses from an earlier generation or earlier driver request. Missing endpoints should age their own panels. |
| C10 / P2 | **Driver dossier is unreachable in the actual page.** Lines 3321–3373 fetch/render detailed laps and stops, but the HTML has no `drvDoss` container; `renderDriver()` immediately returns. Generic delegated row selection also changes focus without `loadDriver()`. Browser DOM confirms the container is absent. | Add a real driver detail drawer, use one selection path for row/map/team clicks, refresh observed data, and guard out-of-order responses. |
| C11 / P2 | **The sidebar FUEL bar is consumption.** Lines 3452–3454 calculate width from `fc.fc * 20`; `fc.fc` is the fuel-consumption field. The label does not say per lap or explain the scale. | Show remaining litres and projected laps. Show a tank percentage only with valid capacity. Keep consumption in a separately labelled L/lap value. |
| C12 / P2 | **Pit counters stop at three native slots, despite an event recorder.** Team Principal and sidebar count `pt0`, `p1`, `p2`; Full Debug says history caps at three. Yet the code records up to 128 observed pit events (lines 1450 onward). | One pit-visit/service model must drive every tab. Distinguish lane visits, completed service, drive-throughs, observed fourth stops and native historical slots. Mark late-join incompleteness. |
| C13 / P2 | **Pit-duration explanation contradicts its own newer data.** Dossier text at 3370 says no box-only clock exists, while 1524–1543 and 1562 onward record the status-3 window as `boxdur`. | Label sampled lane duration and sampled box-state duration accurately, with sampling uncertainty. Do not call either exact crew working time. The corpus's later native service-timer research offers richer context. |
| C14 / P2 | **Contact pairing depends on array order.** Lines 2070–2088 compare both cars' current damage against previous damage, then update the current car's previous value inside the same loop. A can detect B; B then sees A's already updated baseline and may not detect A. | First compute all damage edges, then pair in a second pass. Record neutral co-occurrence with uncertainty, deduplicate and never assign fault from proximity. |
| C15 / P2 | **Team matching uses car/team display text.** Line 3833 matches `cn`; identical car descriptions or missing text can associate unrelated drivers. Broker ABI 8 already supplies reviewed roster-team identity. | Use a session-scoped team key, with roster/VEH provenance and an explicit fallback. Never select the first empty-string match as a teammate. |
| C16 / P2 | **“Strategic range” means nearby positions.** Lines 3840–3843 use position ±2, which says little about pit windows or where a car will rejoin. Pit board says STAY OUT whenever no call/heuristic is present. | Label positional neighbors as such. Strategy should use measured time gaps, pit loss, pace, traffic, fuel and data quality. No positive advice from absence of a pit call. |
| C17 / P2 | **Duplicated focus fields contradict the Pit Wall.** Sidebar top speed uses the old sentinel-prone `fc.ms` (3444), while the Pit Wall uses sampled maxima. Sidebar elapsed uses `fc.et`, despite the same source documenting it as zero in observed races. | Bind all views to shared display models and provenance. Use sampled top speed consistently; make unavailable elapsed time explicit. |
| C18 / P2 | **Debug verification panel is overwritten without focus.** `loadIncidents()` calls `renderDebug(...,null)` at 3860. The normal frame render can restore it, but the polling callback intermittently substitutes the “focus PLAYER” warning even when the player is selected. | Resolve the actual selected identity in every renderer, or render from a single state update. Verification must not depend on which async callback ran last. |
| C19 / P3 | **Driver-of-the-day description and score disagree.** Lines 2120–2134 describe +2 per clean lap, but code grants +2 for the current `clean_lap` boolean; positions gained start when telemetry first saw the car, not necessarily the grid. | Remove from critical driving space or label a documented dashboard score. For a real award persist clean-lap counts and validated grid/capture coverage. It is not an official result or modern F1 rule. |
| C20 / P2 | **Hard-coded warning language can disagree with installed mods.** Tyre life tooltips use 70/40 bands and commentary claims; tyre commentary's feature record describes changed thresholds. Engine-life tooltip says the human fails via overheat while later corpus proves the separate native player's rev/oil/stress life model. | Keep native, mod and dashboard thresholds distinct, parameterize from a verified provider where possible, and remove obsolete explanations. AI vehicle countdown is not the player's native engine-life clock. |

Additional items requiring investigation rather than an asserted bug: whether each native sector field is cumulative or per-sector at the point it is sampled; whether S3 arithmetic always pairs the same completed lap; reliability of per-AI wear mirrors; which wheel/temperature zone interpretations have subsequent live proof; whether aggregate damage tier can establish a specific part was repaired. Use newer corpus evidence to resolve these before promoting semantics.

## Features that would add genuine value

1. **Reliable fuel-to-finish and pit window.** Complete clean-lap consumption, separate caution/wet regimes, remaining distance and reserve. Show “estimated 6.1–6.8 laps, based on 4 comparable laps”; unknown stays unknown. Current fuel projection should be corrected before presenting this as advice.
2. **Measured pit loss and rejoin traffic.** Learn lane+service cost from observed stops, track/session conditions and interruptions; compare “pit now / wait one lap” with nearby traffic. Clearly label counterfactual forecasts and widen uncertainty when no comparable stop exists. Do not assume a universal 20-second pit loss.
3. **Unified race-control card.** SC/RF state, reason, return/restart progress and active instructions from the owning mod. This answers an immediate question the current GREEN badge cannot answer.
4. **Actionable mechanical engineer.** Present symptoms and the currently disclosed diagnosis, cooling/fuel-saving advice from its authoritative provider, and whether the problem was repaired. Distinguish native warnings, mod warnings and dashboard estimates; preserve gameplay uncertainty.
5. **Lap comparison at equal distance.** Speed, brake, throttle and time delta versus own selected clean reference and teammate. Distance-aligned traces enable braking-point and corner-exit insight. Nominal 10–20 Hz sampling is observational, not continuous physics telemetry; any precision claim needs a measured sampling/error budget.
6. **Stint and tyre analysis.** Compound resolved from the actual car/season tyre definitions, tyre age, comparable-lap trend and fuel/condition context. Show degradation evidence without calling changing fuel load or wetness tyre wear. Keep provisional AI wear out of authoritative health percentages.
7. **Qualifying traffic assistant.** Circulating-car count plus physical on-track gaps and selected driver's outlap window. Track loaded/active is insufficient; account for garages, pit exits, stopped cars and lap wrap.
8. **A real driver dossier.** Every observed lap, stint, pit visit, disclosed fault and status change in one reachable drawer; explicit capture gaps and restart segments. This is largely connecting existing collected data correctly.
9. **Post-race replay of observations.** Scrub a local timeline around a spin, failure, SC, RF or pit problem; compare before/after values. This is a recording review, not a reconstructed native replay or proof of causality. Integrate collector recovery and final/complete-history flags.
10. **One-click local diagnostic bundle.** Versions and hashes, plugin/refusal state, capabilities, generation/sequence, panel ages, dropped frames and bounded pre-incident observations. Keep raw race recordings and anonymized usage/crash summaries separate. The DLL must not upload; sharing follows the manager's existing consent model.

Lower priority: editorial Driver of the Day, more decorative gauges, unverified AI “intention” labels, a full camera editor inside telemetry, synthetic DRS/VSC/forecast displays for unavailable providers, or a second independent championship/race-control engine. Their absence is not equivalent to a missing native field.

## Proposed architecture and delivery batches

**Batch 1 — correct the current dashboard.** Fix C01–C06 and misleading sidebar/pit labels; expose the driver drawer; add transport watchdog; remove definite retirement/strategy claims without authoritative evidence. Preserve the read-only localhost/protected-host/game-thread capture design. Completion: documented deterministic counterexamples pass against the actual corrected implementation, and old/new pane values agree.

**Batch 2 — one observation model.** Broker-first snapshots with field quality, process/session/vehicle identity, generation-scoped async queries, complete recent-lap behavior, bounded durable journal and per-panel loss indicators. Use explicit `unknown`, `not_supported`, `not_applicable`, `stale`, `observed`, `estimated` states. Completion: session reset, late join, missed frames, 104-car stress, long races and disconnected/stalled transport retain truthful displays.

**Batch 3 — authoritative mod adapters.** Read-only SC/RF state first; then disclosed MF status and pit service events. Publish separate versioned copied records where the current internal API is insufficient. Completion: provider absent, incompatible, stale, refused and active are all distinguishable; load order cannot create or rewrite another mod's coordination block. Existing frozen ABI 1 and separate MF mapping remain compatible. No new native hooks without broker review.

**Batch 4 — useful analysis.** Distance-aligned lap references, fuel range, measured pit loss/rejoin, stint trends and qualifying traffic. Completion: every estimate identifies input coverage, reference conditions and uncertainty; missing data suppresses confident advice. Native rules and period-specific scoring are data, not modern-F1 assumptions.

**Batch 5 — product polish and integration.** Compact driving view, accessible keyboard/touch controls, user-selected columns/panels, stable focus and local post-race review/export. Extract assets into maintainable modules with deterministic embedding. Resolve mod-standard package metadata/address inventory/settings/reporting exceptions before any release. Human presentation/combined-mod acceptance follows offline checks; do not equate a screenshot or fixture with that gate.
