## 6. Deviations (each chosen as the smallest safe option)

- **D-R1B-1 `lapm` 0, not -1.** Spec 5.5 says -1; `schemas/telemetry.json` says minimum 0, and API contract section 3 defines unknown `lapm` as 0. Contract wins.
- **D-R1B-2 open session = 409.** The id of the open session is kept in the server id table (flag `open`) and never listed. `GET /recordings` still shows no review_id for it (API 10 text unchanged).
- **D-R1B-3 only timed laps are listed.** A lap needs a start and a game time (B2 rule); the first partial lap and laps with no EVENT are not listed. `/laps` `cars` still lists every car seen.
- **D-R1B-4 `channels_seen` = channels the file declares**, not checked per sample (INFERENCE that it matches what the lap stores; verify in R2).
- **D-R1B-5 position and AI flag** come from the newest 64 blocks. A car not in them gets position 0 and `ai` 0. Documented limit.
- **D-R1B-6 `review.stem` is included** (spec 5.5 lists it). It is the session file stem, no path.
- **D-R1B-7 `lap_len` 0 in `/trace/status` and `/trace/data`**, `null` in `/laps` (schema types). META has no lap length (R1-A D-2, `storage_writer.inc` not in this batch's edit list).
- **D-R1B-8 index in error state** (no usable block) answers 404 `review index could not be built`. The spec does not name this case.
- **D-R1B-9 pits and incidents are 404 "not recorded in this recording".** The index keeps lap events only. The writer does store `pit` and `incident` EVENT records (`storage_writer.inc` ~917), so a later batch can add them to the index walk.
- **D-R1B-10 `count` = the index's lap tick count** (`samples`), and the samples are read from the blocks. Equal in the synthetic test; a mismatch would show as a truncated or short list (R2 check).
- **D-R1B-11 trace reads run on the HTTP thread**, one lap's blocks at a time (about 1 MiB per block), with buffers allocated per request. AR-5 (50 ms for `/telemetry` while building) is not measured.
- **D-R1B-12 the adapter starts the index build** on the first request when none runs (spec 5.3). A request during a build gets 503 at once.
