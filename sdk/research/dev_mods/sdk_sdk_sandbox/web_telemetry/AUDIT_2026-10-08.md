## Confirmed source defects and repairs

|---|---|---|
| WT-01 | `tick_thread` polls live vehicle/global pointers; `build_track_json` follows dynamic waypoint memory from the HTTP thread. A low-pointer check does not validate memory lifetime. | A broker-posted callback on the verified game thread copies the fixed vehicle records, globals, flags and waypoint array. HTTP and analysis use only owned mirrors. Synthetic mutation/free tests show isolation and failed reads produce empty data. |
| WT-02 | No protected-host entry or required executable/layout gate; injector-based DllMain starts everything. | Inert DllMain; current host proof/seal/capabilities/generation check; x86 PE/image-range and reviewed SDK code fingerprint gate; broker discovery requiring ABI 15 and lifecycle/snapshot capabilities. | WT-03 | `/action` writes call-to-box, wing state and pace/position directly from worker threads, without reviewed broker ownership. | All action endpoints return 403; action controls removed from the dashboard. No game writes, hooks, native game function calls or injector are present in the candidate. |
| WT-04 | Self-eject uses a 400 ms sleep instead of joining HTTP; HTTP can wait up to a second for a request. DllMain detach deletes locks while worker lifetime is unproven. | Pin module until process exit; no self-eject; explicit HTTP join and broker unregister before releasing the broker API. No worker teardown, sleeps or lock deletion in DllMain. |
| WT-05 | A negative vehicle count reaches the trailing zero-fill starting with a negative car index. | Reject corrupt counts in the producer and clamp defensive readers. Tests cover -1, 105, 0 and maximum 104. |
| WT-06 | Accumulating `_snprintf` return values can move a cursor backwards on old-CRT truncation. Direct comma writes have no independent bound. | Actual-bytes-written formatter, sticky per-thread error, bounded character append, larger worst-case response/log buffers. | WT-07 | JSON escapes only quotes/backslashes; names may contain controls. Track names and pit-stop log names were unescaped. | Escape control characters and size buffers for worst-case escapes; escape track/pit-log names. Browser JSON parsing tests passed. |
| WT-08 | `send` return count is ignored; short nonblocking sends corrupt HTTP bodies/SSE frames. | WT-09 | Player slot can remain from a former session; browser reloads map only on waypoint-count change; empty AIW leaves stale track labels. | Clear/rederive player slot; key browser track reload by session/name/count; clear absent track identity/sectors. | WT-10 | Damage `doomed` consumes previous-tick eng_dead; race-time threshold read as int although canonical broker reads float; pit ring may reuse an open event. | Compute eng_dead first, correct float threshold, refuse an overwritten/completed open pit event. Float fixture passed; other changes statically reviewed. |

The new scheduler also resets its pending latch when the broker session epoch
changes: stale queued callbacks can be discarded without running. Session and
roster changes clear histories, so reused slots do not inherit another car's
state. Failed activation is not reported as success on a second init call.

## Implementation boundaries

The mirror schema reuses existing legacy addresses and the canonical SDK's
fixed vehicle pool/stride. Globals and complete vehicle records must fit the
recognized main executable image; vehicle pointers must be aligned records in
that pool. ReadProcessMemory verifies complete reads and never writes.
Supplementary pointer arrays are bounded and copied before publication. Main
thread sampling uses TryEnterCriticalSection so network/disk work cannot block
the game's callback on this mod's lock. Formatting, file parsing/logging and
network work remain on workers. Sampling requests are approximately 20 Hz.

The producer performs bounded copies, but native callback timing and FPS have
not been measured on the friend's PC. Historical derived field interpretations,
wheel-order assumptions and heuristics remain provisional; this is not a new
validation of every displayed statistic. The copied host header matches the
current Lightloader source. Target payload reference hash:
`6153ED27FCCECF8CCEEE502C97AF6958611D017894715EDC4505D0AE5D095B91`.
This is a contract comparison, not a claim that the exact loader/candidate pair
was run inside a game. Encrypted/unrecognized layouts wait up to three minutes
and then log refusal without starting the listener or reading vehicle data.
