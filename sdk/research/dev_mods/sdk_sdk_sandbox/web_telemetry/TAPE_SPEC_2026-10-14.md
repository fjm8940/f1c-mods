## 0. Owner request and decisions (2026-10-14)
- Request: "a switch to watch either LIVE telemetry (plus the data accumulated in this session) or PREVIOUS
  recordings; the switch makes ALL tabs show data from the live source or the recorded source." Then: "the whole
  tool and ALL the tabs should act as a recording playback tool; all collected data readable and analyzable when

### 2.3 NEW `GET /replay/frame?session=<v2 id>&t=<s>` = one LIVE-shaped `/telemetry` frame at sim time t

- Build: for every car slot seen in the file, the newest tick with sim <= t (clamp t to [t_first, t_last]; a car

### 3.1 The tape (one source object)
- `this.tape = { kind: 'live' | 'rec', rid, t, t_first, t_last, playing, speed }`. LIVE = SSE as today. REC = review
  mode: the Console drives frames itself: while playing, every 100 ms of wall time fetch
  `/replay/frame?session=<rid>&t=<tape t>` (via the existing `opts.fetchJson` path) and pass the doc to
  `this.onFrame(doc)`. Never more than 1 frame request in flight; when behind, skip to the current tape t. Paused =
  one fetch after each seek/step, then none.
- Reuse the Replay page clock: the Replay page and the tape share ONE clock (move `this._rp.t/playing/speed` into
  `this.tape`; the Replay page reads/writes the tape). One RAF/interval loop for the whole console, not per page.
  Keep a timer fallback (setInterval 100 ms) because requestAnimationFrame does not fire in the Browser pane.
- Start: tape at t_first from `/replay/info` (503 = existing "Preparing the recording" wait), paused, one frame
  fetched so every page has data at once.
- Seek backwards or > 5 s forward: clear the short live histories (Engine/Chassis `pchHist`, the Workbench live
  sample buffers) but keep completed laps seeded from `/trace/data`; then fetch the frame. Find the existing
  session-change reset path (new `session_generation`, ~4168) and reuse it if it keeps seeded laps; otherwise add a
  narrow `tapeSeekReset()`.
