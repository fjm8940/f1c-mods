## Findings (most severe first)

| # | Severity | Finding | Evidence | Effect |
|---|---|---|---|---|
| 1 | High | **Scope layers overwrite each other.** `_save_overrides_now` writes the *whole* camera block (Default.cfg values + this scope's edits) for every edited camera. The runtime merges layers key by key, so a Season/Vehicle/Driver file that touches camera X resets every other key of X to Default.cfg, erasing the Global edits for those keys. | gui L1188-1194; runtime `merge_profile` L288-301 | Example: Global COCKPIT PositionOffset edited, then Season 2002 edits only COCKPIT Fov. In 2002 the Global position is gone. |
| 2 | High (verified) | **Out-of-range stock values are silently clamped.** Editors build `DoubleVar(min(high,max(low,v)))`. Saving any component writes the whole tuple, so clamped siblings are saved. | gui L1052; ranges L49-61. Stock cameras outside the ranges: TVCOCKPIT Center (0.5, **5.5**); ONBOARD001/013 OrientationOffset Y **-100.52**; ONBOARD013 PositionOffset (0, **25.52**, **80.05**); ONBOARD017 PositionOffset Y **18.06** | Touching ONBOARD013 Z writes Y=8.0 / Z=8.0 into the game and the profile. That camera moves. |
| 3 | High | **Data race in the runtime.** The worker thread runs every 8 ms (`enforce_mirror_safe_view`): it iterates `g_generic_order` / `g_disabled_views` and writes director +0x34/+0x3C. Meanwhile the game-thread hook `load_for_vehicle` clears and rebuilds the same STL containers whenever the viewed car changes. | runtime L528-535, L447-478, L739-740 | Undefined behaviour or a crash when spectating or cycling TV cameras. The game's camera state is written from a foreign thread. |
| 4 | Medium | **Hidden ONBOARD003-only default.** With no `.views.ini` in any scope, the runtime disables ONBOARD001..017 except 003. The GUI loads no rules and shows all of them enabled. As soon as the user disables one view, a rules file exists and the default switches off, re-enabling the other 16. | runtime L436-444; gui `_load_view_rules` | A fresh install that injects the runtime loses 16 onboard cameras, and the GUI does not show it. |
| 5 | Medium | **Unknown camera names break everything silently.** Override files with names missing from Default.cfg (imports from another install or camera pack, old clones) are appended. The GUI `resolve_slots` then returns None (count < generic). The runtime `apply_all` fails its `count < g_generic_order.size()` check on every frame. | gui L736-738, cam_mem L434; runtime L269-272, L632 | No live editing and no profile applied, with no message. |
| 6 | Medium | **The GUI edits a different value set than the runtime applies.** The editor shows and writes Default.cfg + the *selected* scope. The runtime applies Default → Global → Season → Vehicle → Driver. Stock/Reset write raw Default.cfg values live. | gui L976-990, L1110-1128, L1518-1584 | Editing Global while a Season/Vehicle profile exists looks right, then snaps back on the next session or car change. "Stock" shows a value the game does not use. |
| 7 | Medium | **Driver profile identity.** The key is the `.veh` file name only (`CameraProfiles\Drivers\<name>`). The same file name in different seasons shares one profile. README claims "exact loaded .veh". Driver-scope exports cannot be imported (`_import_target` has no `driver` branch). | gui L437-441, L1235-1256; runtime `driver_key` | Cross-season bleed. The export/import round trip fails for drivers. |
| 8 | Medium | **Season detection differs.** The runtime takes the first 4 consecutive digits anywhere in the path. The GUI uses `(19|20)\d{2}` and offers only 1994-2005. Paths without a year (FIA/V10 mod folders) get no season layer. | runtime `season_key` L402-413; gui L45, L436 | A Season profile can be saved where the runtime never loads it. |
| 9 | Medium | **Process names are fixed** ("F1 Challenge Online.exe", "F1 Challenge 99-02.exe"). | cam_mem L113-117 | Lightloader auto-reports show players on `F1 Challenge 99-02 - Player 1.exe`, `F1C_CMT.exe`, `F1.exe`; the editor finds none without `--exe`. |
| 10 | Medium (release) | **Startup contract.** The runtime loads via `inject.exe` + `DllMain` thread, not the Lightloader host protocol required by the owner standard of 2026-09-24. Its compatibility gate is base address + the first 8/12 bytes of each hooked function. `freecam` detours the same 0x409A00, so whichever loads second refuses. | runtime L103-153, L703-763; freecam.cpp L54 | Must change before this ships as a first-party mod. |
| 11 | Low | **Vehicle edits around a car change.** The 350 ms vehicle save and the 1 s poll race: edits made just before the viewed car changes are lost. Live writes go to "the car the camera views now" with values loaded for the previous car (up to a 1 s window). | gui L570-583, L1424-1429 | Occasional lost edit; transient wrong live values on another car. |
| 12 | Low | **Suspend is incomplete.** "Use Default.cfg temporarily" does not stop ONBOARD redirection: `camera_apply_hook` redirects before checking the suspend event, and the worker never checks it. The comment says the opposite. | runtime L652-664, L528 | Disabled views stay redirected while suspended. |
| 13 | Low | `.veh` save reads with `errors="replace"` and writes UTF-8. All 273 files in the owner install are ASCII; cp1252 files from other mods would be rewritten with U+FFFD (a `.bak` is kept). | gui L633-663 | Data change in non-ASCII mod `.veh` files. |

## What is solid

- Default.cfg is never written. Profile writes stay inside known folders; vehicle paths are confined to
  `SeasonData\Vehicles` (`commonpath` check); the first `.veh` save keeps a `.bak`.
- Memory access fails closed (`plausible_ptr`, the count checks, None on any read failure). The Fov
  mirror pair and the ClipPlanes ×100 transform are the same in the GUI and the runtime.
- Both runtime detours verify whole-instruction bytes and the image base before patching.
- Reset-all needs two confirmations and stays within the active scope.

## Suggested order of work

1. Save only the edited keys per scope (fixes #1). Remove slider clamping, or widen the ranges and
   never write untouched components (#2). These two silently corrupt user cameras.
2. Runtime: do the redirect/rebuild only on the game thread (drop the worker's container access or
   guard it with a lock and a snapshot) (#3). Honour suspend in both paths (#12).
3. Make the default ONBOARD policy explicit and visible in the GUI (#4). Skip or warn about unknown
   camera names instead of failing silently (#5).
4. Show and edit the effective layered value, and mark which layer each value comes from (#6).
   Align driver/season identity between the GUI and the runtime (#7, #8).
5. Before any public release: Lightloader host protocol and coexistence with freecam (#10),
   renamed-EXE detection (#9), tests for scope merging and the runtime parser, and a rebuild of the
   packaged EXE from the current source.
